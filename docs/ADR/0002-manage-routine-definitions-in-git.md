# 0002. routine の定義を git で管理し、クラウド側へ同期する

- 日付: 2026-09-30
- 状態: Accepted

## 背景
routine は claude.ai 上（Cowork）で作成され、prompt もスケジュールもクラウド側にしか存在しなかった。
状況に応じて更新していくと、何がいつなぜ変わったかを追えなくなる。また他者に共有する手段がなかった。

## 決定
このディレクトリ（`odd12258053/news`）を git リポジトリとし、routine ごとに
`routine.yaml`（設定）・`prompt.md`（指示本体）・`CHANGELOG.md`（理由）を置く。
ファイルを正とし、クラウド側へは `scripts/render.py` で生成した body を `RemoteTrigger` で反映する。
リポジトリは GitHub で公開し、ライセンスは MIT とする。

## 理由
検討した選択肢:
1. **ファイルを正として git 管理し、クラウドへ同期する（採用）** — 変遷は git 履歴で自然に残り、公開も GitHub で済む。
2. クラウド側を正とし、変更のたびにスナップショットを書き出す — 書き忘れると履歴が欠ける。編集もクラウド UI に依存する。

1 は反映手順が一手間増えるが、履歴の確実性と公開のしやすさが上回る。

## 影響
- クラウド UI から直接編集すると、ファイルと乖離する。編集は必ずファイル側で行い、同期する。
- routine の削除は API からできないため、クラウド UI で削除した上でファイルも削除する。
- 既存 routine（週刊AIダイジェスト）は 2026-09-30 時点の内容をそのまま取り込み、ベースラインとした。
