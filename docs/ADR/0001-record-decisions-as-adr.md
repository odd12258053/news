# 0001. 決定事項を ADR として記録する

- 日付: 2026-09-30
- 状態: Accepted

## 背景
このリポジトリの目的の一つは「スケジュール内容がどう変わっていったか」の変遷を残すこと。
個々の routine の変更理由は CHANGELOG に書くが、リポジトリ全体の方針や構成に関する判断は
どこにも残らないままになりやすい。

## 決定
運用方針・構成・ツール選択などの決定は `docs/ADR/` に 1 決定 1 ファイルで記録する。
書式と採番は `docs/ADR/README.md` に従う。Claude Code にもこのルールを CLAUDE.md で指示する。

## 理由
- 決定の「背景・理由・影響」を分けて書く定型があると、後から読む人（将来の自分や他者）が判断の前提を追える。
- 決定を覆すときも古い ADR を残すので、変遷そのものが記録になる。

## 影響
- 方針を決めるたびに ADR を 1 本書くコストがかかる。小さな判断は CHANGELOG や README で済ませてよい。
- 公開後は ADR も公開されるため、個人情報や機密を書かない。
