# 0004. 変更の理由を routine ごとの CHANGELOG に残す

- 日付: 2026-09-30
- 状態: Accepted

## 背景
prompt の差分は git log で分かるが、「なぜその行を変えたか」「変えた結果どうなったか」は差分には現れない。
情報収集タスクは実行結果を見ながら調整していくものなので、試行の記録が価値を持つ。

## 決定
routine ごとに `CHANGELOG.md` を置き、変更のたびに同じコミットで
「日付 / 何を変えたか / なぜ / 結果（分かれば後追いで）」を新しい順に書く。
差分の再掲はしない。

## 理由
- リポジトリ全体の ADR とは粒度が違う。prompt の一文を変えるたびに ADR を書くのは重すぎる。
- 「結果」を後から追記できるようにしておくと、うまくいかなかった変更も記録として残る。

## 影響
- CHANGELOG の更新を伴わない routine 変更はレビューで差し戻す（CLAUDE.md に明記）。
- 実行結果の確認は `RemoteTrigger list_runs` / `get_run_log` で行い、要点だけを CHANGELOG に書く。
