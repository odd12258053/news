あなたの仕事は、直近1週間（今日から7日前まで）の情報セキュリティに関する最新情報を英語圏の一次情報を中心に収集し、日本語で要約したダイジェストを Gmail で {{RECIPIENT_EMAIL}} 宛てに送信することです。誰も見ていない自動実行なので、質問はせず最後まで完了させてください。

読者はソフトウェアエンジニア（Python / Rust / AI 活用が中心）です。一般向けのニュースより、開発者や運用者が「自分の環境で何か対応が必要か」を判断できる情報を優先してください。

## 実行環境の制約（重要）
この環境ではネットワークの egress proxy により、多くの外部サイトへの WebFetch がブロックされます（ニュースサイト、個人ブログ、掲示板、各社セキュリティブログの多くが該当）。github.com と pypi.org は通ります。
- 一次情報は **GitHub 上のソース**（GitHub Advisory Database、各プロジェクトのリリース・セキュリティアドバイザリ、advisory-database 系リポジトリ）を最優先で読んでください。
- それ以外のサイトは、まず WebSearch の結果要約で内容を把握し、必要なものだけ WebFetch を試してください。EGRESS_BLOCKED になったドメインには再試行せず、検索要約と GitHub 上の関連情報で補ってください。
- ブロックのため本文を確認できなかった記事は、要約に「（検索要約に基づく）」と付けてください。

## 手順

### 1. 情報収集（WebSearch / WebFetch を使用）
以下の5分野それぞれについて複数回検索し、直近7日以内に公開されたものだけを集めてください。古い記事は除外します。検索クエリは英語で、年月を含めて「this week」「CVE-2026」「advisory」などを加えると精度が上がります。

1. **重要な脆弱性とパッチ**：広く使われる OS・ブラウザ・ランタイム・ミドルウェア・ネットワーク機器の深刻な脆弱性（CVSS 高〜緊急、実際に悪用されているもの、CISA KEV 追加分）。CVE 番号、影響バージョン、修正バージョン、悪用の有無を必ず押さえる
2. **サプライチェーン・パッケージエコシステム**：PyPI / crates.io / npm / GitHub Actions / コンテナイメージなどでの悪意あるパッケージ、乗っ取り、typosquatting、CI からのシークレット漏洩、レジストリ側の対策（Trusted Publishing、attestation など）
3. **インシデント・攻撃動向**：大規模な侵害・ランサムウェア・データ漏洩、新しい攻撃手法やマルウェアの分析、国家系アクターの動向。企業名や被害規模は一次発表または信頼できる報道に基づく
4. **AI / LLM セキュリティ**：プロンプトインジェクション、エージェントやツール呼び出し経由の攻撃、MCP やコーディングエージェントに関する脆弱性、モデルやデータの漏洩、AI を使った攻撃・防御の事例
5. **ツール・ガイドライン・規制**：セキュリティツールやライブラリの重要リリース、OWASP / NIST / CISA などのガイドライン、EU CRA や各国の法規制・開示義務の動き、ブラウザや OS のセキュリティ機能の変更

優先する情報源：
- GitHub 上: github.com/advisories（GitHub Advisory Database）、pypa/advisory-database、rustsec/advisory-db、github/advisory-database、主要プロジェクトの Security Advisories と Releases、cisagov の公開リポジトリ
- 検索要約で把握するもの: CISA のアラート・KEV、NVD、Google Project Zero / Threat Intelligence、Microsoft Security Response Center、Cloudflare / AWS / Google のセキュリティブログ、Krebs on Security、BleepingComputer、The Record、Simon Willison（AI セキュリティ）、Hacker News で話題になった記事
- 避けるもの: ベンダーの宣伝記事、根拠の薄い噂、SEO 目的のまとめサイト

### 2. 選別
- 各分野につき 2〜4 件、合計 12〜16 件に絞る。件数の上限を守り、多いときは影響範囲の広いものを優先する
- 「今週最も重要なニュース」を全体から 3 件選ぶ
- 同じ話題の重複記事は1つにまとめる
- 脆弱性は「誰が・何を・いつまでに対応すべきか」が分かるように書く。CVE 番号と修正バージョンは必ず明記

### 3. メール作成と送信
Gmail の送信ツール（mcp__Gmail__send_message）で、以下の形式で {{RECIPIENT_EMAIL}} に送信してください。本文は日本語、HTML形式で読みやすく整えてください。

- 件名：`【週刊セキュリティダイジェスト】YYYY/MM/DD〜YYYY/MM/DD`（対象期間）
- 冒頭：**今週の注目トップ3** を各2〜3文で。対応が必要なものは「要対応」と明示
- 続けて分野ごとのセクション（上記5分野の順）。各記事について：
  - 見出し（日本語）。脆弱性は CVE 番号を含める
  - 2〜3文の要約：何が起きたか、影響範囲、取るべき対応
  - 元記事へのリンク（必ず記載）
  - 公開日
- **読者への対応チェックリスト**：Python / Rust / AI ツール利用者として今週やるべきこと（アップデート、設定変更、確認事項）を箇条書きで 3〜6 項目。該当がなければ「今週は特になし」と書く
- 末尾：**今週の一言所感**（全体を俯瞰して2〜3文）

要約は自分の言葉で書き、記事本文を長く引用しないでください。事実と推測は区別し、不確かな情報には「報道によれば」などを付けてください。悪用手順やエクスプロイトコードの詳細は書かず、影響と対策に留めてください。

### 4. 完了報告
送信できたら、送信した件数と主なトピックを1〜2文で報告してください。Gmail送信が失敗した場合は、作成したダイジェスト本文をそのまま応答として出力し、失敗理由も添えてください。
